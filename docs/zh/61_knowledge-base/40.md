# 官方前端升级与定制补丁维护

Java MaxKB 以官方前端为基线，由 Java 后端适配接口。独立部署、文件 ID 传递和 Agent 过程展示等必要定制单独保存，便于更新后核对和恢复。

## 保存内容

Java 仓库的 `docs/customizations/2026-10-03` 保存前端源代码补丁、单独的依赖锁文件补丁、环境变量模板及文件校验清单。说明文件逐项记录修改原因，并区分本次新增和保留的历史定制。

基准提交必须对应实际仓库。当前快照来自已有 fork 的合并目标，不直接当作官方上游提交。官方升级前记录 upstream 地址和准确提交，再按功能选择恢复必要的差异。

## 恢复步骤

1. 保存工作区，完成已有合并，更新官方前端。
2. 在 Java 仓库执行 `scripts/Apply-FrontendCustomizations.ps1`，通过 `-Repository` 指定前端仓库，通过 `-Bundle` 指定补丁目录。默认只运行适用性检查。
3. 检查通过后使用 `-Apply` 应用；冲突时按修改记录人工合并。
4. 合入环境变量模板并重新安装依赖。锁文件补丁默认不应用，升级后优先生成适配新上游的锁文件。
5. 运行前端构建，使用界面验证上传解析、文件 ID、Hash 路由、分享聊天、SSE、迭代检索及上下文压缩。

导出脚本 `scripts/Export-FrontendCustomizations.py` 不修改源仓库索引，在临时目录应用补丁后逐文件校验。它只保存前端受控差异及源码新增文件，环境模板不包含凭证。

## 后端约定

模型生成复用 `java-openai` 的 `UniChatClient`，业务层只组织提示词、配置及校验结果。上下文仅在 token 超过预算时压缩，短会话及仅超过轮数的会话不会触发摘要请求。实现细节见 [迭代检索与上下文压缩](32.md)。

Maven 构建使用 `-Dgpg.skip=true` 跳过签名。新增及修改的 Java、TypeScript 条件语句使用花括号。数据库迁移、客户端扩展、配置与验收结果随代码同步记录。

## 数据库模型目录补充

本次模型管理没有修改前端代码，原页面已支持手动输入模型 ID。新快照保留之前的前端差异，并更新 Java 后端、迁移与同步脚本。`Export-BackendCustomizations.py` 导出后端源码和脚本，并在临时目录验证补丁及文件校验值；不导出密钥、日志和本地配置。模型功能见[35](35.md)。
