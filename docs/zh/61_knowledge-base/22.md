# 多文档解析

[[toc]]

## 当前实现与接口说明

Java 后端先检测文件实际内容，再选择解析策略。当前处理 PDF、DOCX、DOC、XLS/XLSX、常用文本和 HTML、可识别图片及受限 ZIP 文档集合。不要仅凭文件扩展名决定解析方式，也不要将尚未实现的格式列为已支持。

文字 PDF 使用文本提取，扫描页使用 Gitee PaddleOCR-VL-1.5，混合 PDF 逐页选择；DOCX 保留正文和表格，正文极少且含图片时对内嵌图片 OCR；表格按工作表提取。完整格式、容量限制和策略标识

## 文档检测与解析策略

解析服务先检查内容，再选择路径。PDF 通过文件头识别，即使扩展名不正确也能识别。

| 文档特征 | 策略 | 结果标识 |
| --- | --- | --- |
| 可提取有效文字的 PDF 页面 | 按阅读顺序提取文字，保留页码 | `pdf-text` |
| 扫描 PDF 页面或无法可靠提取文字的页面 | 调用 PaddleOCR，按原页序合并 | `pdf-ocr` |
| 同时含文字页和扫描页的 PDF | 逐页选择提取或 OCR | `pdf-mixed` |
| DOCX 正文与表格 | 提取段落、表格结构 | `docx-structure` |
| DOCX 正文极少但含图片 | 提取内嵌图片并 OCR | `docx-ocr` |
| DOC | 提取正文 | `doc-text` |
| XLS、XLSX | 按工作表和行提取显示值 | `spreadsheet-structure` |
| TXT、Markdown、日志、CSV、JSON、HTML | 文本解码，HTML 提取可见正文 | `text` |
| PNG、JPEG、TIFF 等可识别图片 | OCR | `image-ocr` |
| ZIP | 在内存中读取文档并合并，不解压到磁盘 | `zip-documents` |

空文件会被拒绝。单个上传文件最多 100 MB；ZIP 最多 50 个成员文件，解压后总量最多 100 MB，不支持嵌套 ZIP。DOCX 正文和图片另有解析容量限制。PDF 文字页检测采用启发式规则，复杂排版、文字层与图片混排的文档仍应检查分段预览。

OCR 结果按内容摘要缓存。正文用于分段和检索，不把 OCR 服务临时图片地址作为知识片段的必要内容。解析预览返回 `parse_strategy`、`page_count` 和文件 `id`。

解析预览返回文件 `id`、策略与页数。前端提交确认后的分段时必须回传该文件 ID，后端据此建立文档关联。解析结果应由用户检查后再入库。

### 已实现能力一览

| 输入 | 判定依据 | 解析方式 | 策略标识 |
| --- | --- | --- | --- |
| 文字型 PDF | 头部 `%PDF-` | PDFBox 逐页文本提取 | `pdf-text` |
| 扫描型 PDF | 头部 `%PDF-`，各页可读字符不足 | 逐页渲染后远程 OCR | `pdf-ocr` |
| 混合型 PDF | 头部 `%PDF-`，部分页有文本 | 逐页在文本提取与 OCR 之间选择 | `pdf-mixed` |
| DOCX | ZIP 头 `PK` 且文件名以 `.docx` 结尾 | 解析 `word/document.xml` 的段落与表格 | `docx-structure` |
| 图片型 DOCX | 同上，但正文可读字符不足 40 且含 `word/media/` 图片 | 结构文本 + 内嵌图片 OCR | `docx-ocr` |
| XLS / XLSX | 文件名后缀 | 按工作表逐行导出为 Markdown 表格 | `spreadsheet-structure` |
| DOC | 文件名后缀 | WordExtractor 提取纯文本 | `doc-text` |
| ZIP | 文件名后缀 | 逐条目递归调用同一解析器 | `zip-documents` |
| TXT / MD / LOG / CSV / JSON | 文件名后缀 | UTF-8 解码，失败回退 GB18030 | `text` |
| HTML / HTM | 文件名后缀 | jsoup 去标签取正文 | `text` |
| PNG / JPG / JPEG / TIFF 等 | `ImageIO.read` 可解码 | 直接送入远程 OCR | `image-ocr` |

### 容量与安全边界

| 限制项 | 阈值 | 触发结果 |
| --- | --- | --- |
| 单个上传文件 | 100 MB（前后端各校验一次） | `文件不能超过100MB` |
| ZIP 内文件个数 | 50 个，且不允许嵌套 ZIP | `ZIP最多包含50个文件，不支持嵌套ZIP` |
| ZIP 解压后总大小 | 100 MB | `ZIP解压后的内容不能超过100MB` |
| DOCX 内嵌图片 | 50 张，单张 20 MB | `DOCX内嵌图片过多或过大` |
| 表格 | 10 万行、500 列、输出 20 MB | `表格内容过大，请拆分后上传` |
| PDF 加密 | PDFBox `isEncrypted()` | `请先解密PDF文件` |
| 解析结果为空 | `result.text().isBlank()` | `未提取到内容，请检查文档或使用扫描PDF` |

DOCX 的 XML 解析关闭了 DTD 与外部实体，ZIP 采用流式读取且从不落地解压路径，因此压缩包里的相对路径不会被写入磁盘。

## 解析器：`DocumentParsingService`

解析入口是 `parse(byte[] data, String filename)`，返回一个包含策略、正文和页数的记录对象：

```java
package nexus.io.mosskb.service.kb;

import java.io.*;
import java.nio.charset.StandardCharsets;
import java.util.*;
import java.util.zip.*;
import javax.xml.XMLConstants;
import javax.xml.parsers.DocumentBuilderFactory;
import org.w3c.dom.*;
import org.apache.pdfbox.pdmodel.PDDocument;
import org.apache.pdfbox.text.PDFTextStripper;
import nexus.io.gitee.*;
import nexus.io.db.activerecord.Db;
import nexus.io.tio.utils.crypto.Md5Utils;

/** Detect the actual document structure before selecting text extraction or OCR. */
public class DocumentParsingService {
  public record Parsed(String strategy, String text, int pages) {}

  public Parsed parse(byte[] data, String filename) throws Exception {
    if (data == null || data.length == 0) {
      throw new IllegalArgumentException("文件为空");
    }
    if (data.length > 100 * 1024 * 1024) {
      throw new IllegalArgumentException("文件不能超过100MB");
    }
    String name = filename.toLowerCase(Locale.ROOT);
    Parsed result;
    if (new String(data, 0, Math.min(5, data.length), StandardCharsets.US_ASCII).equals("%PDF-")) {
      // PDF：逐页判断
    } else if (data.length > 4 && data[0] == 'P' && data[1] == 'K' && name.endsWith(".docx")) {
      // DOCX：结构提取，必要时补图片 OCR
    } else if (name.endsWith(".xlsx") || name.endsWith(".xls")) {
      // 表格：按工作表提取
    } else if (name.endsWith(".doc")) {
      // 旧版 Word
    } else if (name.endsWith(".zip")) {
      // 受限 ZIP 文档集合
    } else if (name.matches(".*\\.(txt|md|log|csv|json|html|htm)$")) {
      // 文本与 HTML
    } else if (javax.imageio.ImageIO.read(new ByteArrayInputStream(data)) != null) {
      // 图片：直接 OCR
      result = new Parsed("image-ocr", ocr(data, filename), 1);
    } else {
      throw new IllegalArgumentException("不支持的文件格式，请转换为PDF、DOCX、TXT或图片后上传");
    }
    if (result.text().isBlank()) {
      throw new IllegalArgumentException("未提取到内容，请检查文档或使用扫描PDF");
    }
    return result;
  }
}
```

判定顺序决定了一个重要行为：**PDF 与 DOCX 走魔数判定，其余格式才看扩展名**。因此把扫描版 PDF 改名为 `.txt` 依旧按 PDF 处理，这也是单元测试里刻意覆盖的场景。

### PDF：逐页在文本与 OCR 之间选择

PDF 不做整篇二选一，而是逐页判定。单页去掉空白字符后剩余不足 40 个字符、或出现替换字符 `\uFFFD`，就认为该页需要 OCR：

```java
  private static final int MIN_NATIVE_CHARS = 40;

  private Parsed parsePdf(byte[] data) throws Exception {
    try (PDDocument pdf = PDDocument.load(data)) {
      if (pdf.isEncrypted()) {
        throw new IllegalArgumentException("请先解密PDF文件");
      }
      PDFTextStripper stripper = new PDFTextStripper();
      stripper.setSortByPosition(true);
      String sourceHash = Md5Utils.md5Hex(data);
      StringBuilder text = new StringBuilder();
      int nativePages = 0;
      for (int i = 1; i <= pdf.getNumberOfPages(); i++) {
        stripper.setStartPage(i);
        stripper.setEndPage(i);
        String page = stripper.getText(pdf);
        if (page.replaceAll("\\s", "").length() >= MIN_NATIVE_CHARS && !page.contains("\uFFFD")) {
          text.append("\n\n> Page ").append(i).append("\n\n").append(page);
          nativePages++;
        } else {
          try (PDDocument single = new PDDocument(); ByteArrayOutputStream out = new ByteArrayOutputStream()) {
            single.importPage(pdf.getPage(i - 1));
            single.save(out);
            text.append("\n\n> Page ").append(i).append("\n\n").append(ocrPdfPage(sourceHash, i, out.toByteArray()));
          }
        }
      }
      String strategy = nativePages == pdf.getNumberOfPages() ? "pdf-text"
          : nativePages == 0 ? "pdf-ocr" : "pdf-mixed";
      return new Parsed(strategy, text.toString(), pdf.getNumberOfPages());
    }
  }
```

要点：

- **页序不会被并行打乱**。OCR 是逐页同步等待的，正文严格按物理页码顺序拼接。
- **每页都写入 `> Page N` 标记**，让后续分段与大模型引用能定位到页。
- **单页导出会生成新的 PDF 内部对象 ID**，所以缓存键不能用导出后的字节，而要用「原始文件内容 + 页码」，见下节。
- `strategy` 由「原生页数量」推导：全部原生为 `pdf-text`，全部走 OCR 为 `pdf-ocr`，其余为 `pdf-mixed`。

### OCR：远程任务、轮询与缓存

OCR 统一走 `ocrWithCache`，先查缓存，未命中才提交远程任务：

```java
  protected String ocr(byte[] data, String filename) throws Exception {
    return ocrWithCache(data, filename, Md5Utils.md5Hex(data) + ":paddle15");
  }

  protected String ocrPdfPage(String sourceHash, int page, byte[] pageData) throws Exception {
    // Serializing a PDF page can generate a fresh internal document ID. Cache by
    // original file content and page number instead of the transient PDF bytes.
    return ocrWithCache(pageData, "page.pdf", sourceHash + ":page:" + page + ":paddle15");
  }

  private String ocrWithCache(byte[] data, String filename, String hash) throws Exception {
    String cached = readOcrCache(hash);
    if (cached != null && !cached.isBlank()) {
      return textOnly(cached);
    }
    String markdown = recognize(data, filename);
    writeOcrCache(hash, markdown);
    return markdown;
  }

  protected String readOcrCache(String hash) {
    return Db.queryStr("select content from moss_kb_document_markdown_cache where id=?", hash);
  }

  protected void writeOcrCache(String hash, String markdown) {
    Db.update("insert into moss_kb_document_markdown_cache(id,content) values(?,?) "
        + "on conflict(id) do update set content=excluded.content", hash, markdown);
  }
```

缓存表结构极简，主键即缓存键：

```sql
CREATE TABLE "public"."moss_kb_document_markdown_cache" (
  "id" VARCHAR PRIMARY KEY,
  "target" VARCHAR,
  "content" TEXT
);
```

真实提交与轮询逻辑如下，供应商返回的是异步任务，必须轮询到终态：

```java
  protected String recognize(byte[] data, String filename) throws Exception {
    GiteeClient client = new GiteeClient();
    GiteeDocumentParseRequest request = new GiteeDocumentParseRequest();
    request.setModel(GiteeModels.PADDLEOCR_VL_1_5);
    request.setPrompt(GiteePromptConst.pdf_to_markdown_prompt);
    request.setInclude_image(false);
    request.setInclude_image_base64(false);
    GiteeTaskResponse task = client.parseDocument(data, filename, request);
    long deadline = System.nanoTime() + java.util.concurrent.TimeUnit.MINUTES.toNanos(8);
    while (!Arrays.asList("success", "succeeded", "completed")
        .contains(String.valueOf(task.getStatus()).toLowerCase(Locale.ROOT))) {
      if (task.getStatus() == null || task.getTask_id() == null) {
        throw new IOException("OCR服务未返回有效任务状态");
      }
      if (Arrays.asList("failed", "failure", "cancelled", "canceled")
          .contains(task.getStatus().toLowerCase(Locale.ROOT))) {
        throw new IOException("OCR任务失败: " + task.getTask_id());
      }
      if (System.nanoTime() > deadline) {
        throw new IOException("OCR任务超时: " + task.getTask_id());
      }
      Thread.sleep(2000);
      task = client.getTask(task.getTask_id());
    }
    String markdown = textOnly(GiteeSimpleMarkdownUtils.toMarkdown(task.getOutput(), null));
    if (markdown == null || markdown.isBlank()) {
      throw new IOException("OCR未返回正文");
    }
    return markdown;
  }

  private String textOnly(String markdown) {
    if (markdown == null) {
      return "";
    }
    return markdown.replaceAll("(?is)<img\\b[^>]*>", "")
        .replaceAll("(?is)<div[^>]*>\\s*</div>", "").replaceAll("!\\[[^\\]]*\\]\\([^)]*\\)", "");
  }
```

设计取舍：

- **只取正文**：`include_image` 与 `include_image_base64` 都关闭，返回结果再剥掉 `<img>`、空 `<div>` 与 Markdown 图片语法，避免把 base64 图片带进分段和向量。
- **超时 8 分钟**：超时或失败都抛出带 `task_id` 的异常，前端能直接展示可追踪的错误。
- **模型名使用常量**：`GiteeModels.PADDLEOCR_VL_1_5` 而不是裸字符串，便于后续切换 OCR 模型。
- **缓存键带模型后缀**：`md5(content) + ":paddle15"`，换模型后旧缓存不会污染新结果。
- **重复上传不重复计费**：同一文件改名后再次解析，整篇缓存命中；PDF 的每一页也各有一条缓存，中断重试只需补齐缺失页。

### DOCX：段落、表格与内嵌图片

DOCX 不走 ZIP 集合解析，而是单独读取 `word/document.xml`，同时关闭 DTD 与外部实体：

```java
  private static final int DOCX_XML_LIMIT = 20 * 1024 * 1024;

  private String docx(byte[] data) throws Exception {
    try (ZipInputStream zip = new ZipInputStream(new ByteArrayInputStream(data))) {
      ZipEntry entry;
      while ((entry = zip.getNextEntry()) != null) {
        if (!entry.getName().equals("word/document.xml")) {
          continue;
        }
        byte[] xml = zip.readNBytes(DOCX_XML_LIMIT + 1);
        if (xml.length > DOCX_XML_LIMIT) {
          throw new IllegalArgumentException("DOCX内容过大");
        }
        DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
        factory.setNamespaceAware(true);
        factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
        factory.setAttribute(XMLConstants.ACCESS_EXTERNAL_DTD, "");
        factory.setAttribute(XMLConstants.ACCESS_EXTERNAL_SCHEMA, "");
        Document doc = factory.newDocumentBuilder().parse(new ByteArrayInputStream(xml));
        StringBuilder out = new StringBuilder();
        Node body = doc.getElementsByTagNameNS("*", "body").item(0);
        for (Node node = body.getFirstChild(); node != null; node = node.getNextSibling()) {
          if ("p".equals(node.getLocalName())) {
            out.append(text(node)).append("\n\n");
          }
          if ("tbl".equals(node.getLocalName())) {
            NodeList rows = ((Element) node).getElementsByTagNameNS("*", "tr");
            for (int r = 0; r < rows.getLength(); r++) {
              NodeList cells = ((Element) rows.item(r)).getElementsByTagNameNS("*", "tc");
              out.append('|');
              for (int c = 0; c < cells.getLength(); c++) {
                out.append(text(cells.item(c)).replace("|", "\\|")).append('|');
              }
              out.append('\n');
              if (r == 0) {
                out.append('|');
                for (int c = 0; c < cells.getLength(); c++) {
                  out.append("---|");
                }
                out.append('\n');
              }
            }
            out.append('\n');
          }
        }
        return out.toString();
      }
    }
    throw new IllegalArgumentException("DOCX缺少正文");
  }

  private String text(Node node) {
    StringBuilder out = new StringBuilder();
    NodeList texts = ((Element) node).getElementsByTagNameNS("*", "t");
    for (int i = 0; i < texts.getLength(); i++) {
      out.append(texts.item(i).getTextContent());
    }
    return out.toString();
  }
```

- 段落转成 Markdown 段，表格转成**带表头分隔线**的 Markdown 表格，单元格内的 `|` 会转义，列数不会错位。
- 内嵌图片走 OCR 只在正文可读字符不足 40 时触发，判断与图片收集都在 `parse` 分支里完成：

```java
    } else if (data.length > 4 && data[0] == 'P' && data[1] == 'K' && name.endsWith(".docx")) {
      String extracted = docx(data);
      if (extracted.replaceAll("\\s", "").length() < MIN_NATIVE_CHARS) {
        String images = docxImages(data);
        result = new Parsed(images.isBlank() ? "docx-structure" : "docx-ocr", extracted + images, 0);
      } else {
        result = new Parsed("docx-structure", extracted, 0);
      }
    }
```

`docxImages` 只遍历 `word/media/` 且能做图片解码的条目，最多 50 张、单张不超过 20 MB，超限直接报错而不是静默截断。

### 表格、旧版 DOC 与 ZIP

表格用 POI 的 `DataFormatter` 输出**显示值**，公式单元格取缓存计算值，避免把公式串写进正文：

```java
  private String spreadsheet(byte[] data) throws Exception {
    try (org.apache.poi.ss.usermodel.Workbook workbook =
        org.apache.poi.ss.usermodel.WorkbookFactory.create(new ByteArrayInputStream(data))) {
      org.apache.poi.ss.usermodel.DataFormatter formatter =
          new org.apache.poi.ss.usermodel.DataFormatter(Locale.ROOT);
      formatter.setUseCachedValuesForFormulaCells(true);
      StringBuilder out = new StringBuilder();
      int rows = 0;
      for (org.apache.poi.ss.usermodel.Sheet sheet : workbook) {
        out.append("\n## ").append(sheet.getSheetName()).append("\n\n");
        for (org.apache.poi.ss.usermodel.Row row : sheet) {
          if (++rows > 100000 || row.getLastCellNum() > 500 || out.length() > 20 * 1024 * 1024) {
            throw new IllegalArgumentException("表格内容过大，请拆分后上传");
          }
          for (int i = 0; i < row.getLastCellNum(); i++) {
            out.append('|').append(formatter.formatCellValue(row.getCell(i))
                .replace("|", "\\|").replace('\n', ' '));
          }
          out.append("|\n");
        }
      }
      return out.toString();
    }
  }
```

旧版 `.doc` 用 `WordExtractor` 取纯文本：

ZIP 只作为「文档集合」处理，**递归调用同一个解析器**，因此包内的 PDF、DOCX、表格都能各自按真实内容解析；包内出现 ZIP 直接拒绝：

```java
  private String archive(byte[] data) throws Exception {
    StringBuilder out = new StringBuilder();
    try (ZipInputStream zip = new ZipInputStream(new ByteArrayInputStream(data))) {
      ZipEntry entry;
      int count = 0;
      long total = 0;
      while ((entry = zip.getNextEntry()) != null) {
        if (entry.isDirectory()) {
          continue;
        }
        String name = entry.getName().replace('\\', '/');
        if (name.startsWith("__MACOSX/") || name.endsWith(".DS_Store")) {
          continue;
        }
        if (name.toLowerCase(Locale.ROOT).endsWith(".zip") || ++count > 50) {
          throw new IllegalArgumentException("ZIP最多包含50个文件，不支持嵌套ZIP");
        }
        byte[] bytes = zip.readNBytes(100 * 1024 * 1024 + 1);
        total += bytes.length;
        if (total > 100 * 1024 * 1024) {
          throw new IllegalArgumentException("ZIP解压后的内容不能超过100MB");
        }
        out.append("\n\n# ").append(name).append("\n\n").append(parse(bytes, name).text());
      }
    }
    return out.toString();
  }
```

每个条目都会以 `# 文件名` 作为一级标题插入，解析结果里保留了压缩包内的相对路径，方便用户核对来源。

### 文本与 HTML

文本类文件优先按 UTF-8 严格解码，遇到非法字节序列再回退 GB18030，覆盖旧版中文文档：

```java
    } else if (name.matches(".*\\.(txt|md|log|csv|json|html|htm)$")) {
      String text;
      try {
        text = StandardCharsets.UTF_8.newDecoder()
            .decode(java.nio.ByteBuffer.wrap(data)).toString();
      } catch (java.nio.charset.CharacterCodingException e) {
        text = new String(data, java.nio.charset.Charset.forName("GB18030"));
      }
      if (name.matches(".*\\.(html|htm)$")) {
        text = org.jsoup.Jsoup.parse(text).wholeText();
      }
      result = new Parsed("text", text, 0);
    }
```

这里用的是 `newDecoder().decode(...)`（严格模式）而不是 `new String(data, UTF_8)`，两者的区别正是回退逻辑能否生效的关键。

## 远端 OCR 依赖的接口形态

客户端提供「按文件」「按字节数组」以及「图片 OCR」三种入口，本项目使用字节数组形式，从而不落地临时文件：

```java
  public GiteeTaskResponse parseDocument(byte[] data, String filename, GiteeDocumentParseRequest requestEntity) {
    String suffix = FilenameUtils.getSuffix(filename);
    String contentType = ContentTypeUtils.getContentType(suffix);

  public GiteeTaskResponse getTask(String taskId) {
```

## 分段与解析预览

解析完成后交给 `MossKbDocumentSplitService` 做 token 级分段，并把策略与页数一并返回给前端：

```java
package nexus.io.mosskb.service.kb;

import java.io.IOException;
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.ExecutionException;

import com.jfinal.kit.Kv;

import dev.langchain4j.data.document.Document;
import dev.langchain4j.data.document.DocumentSplitter;
import dev.langchain4j.data.document.splitter.DocumentSplitters;
import dev.langchain4j.data.segment.TextSegment;
import lombok.extern.slf4j.Slf4j;
import nexus.io.model.result.ResultVo;
import nexus.io.model.upload.UploadResult;
import nexus.io.openai.token.OpenAiTokenizer;

@Slf4j
public class MossKbDocumentSplitService {

  public ResultVo split(byte[] data, UploadResult vo) throws IOException, InterruptedException, ExecutionException {
    String filename = vo.getName();
    DocumentParsingService.Parsed parsed;
    try {
      parsed = new DocumentParsingService().parse(data, filename);
    } catch (Exception e) {
      throw new IOException(e.getMessage(), e);
    }
    String markdown = parsed.text();
    List<TextSegment> segments = split(markdown);
    Kv fileSplitResult = Kv.by("name", filename).set("id", vo.getId());
    List<Kv> contents = new ArrayList<>();
    for (TextSegment textSegment : segments) {
      contents.add(Kv.by("title", "").set("content", textSegment.text()));
    }
    fileSplitResult.set("content", contents).set("parse_strategy", parsed.strategy()).set("page_count", parsed.pages());
    List<Kv> results = new ArrayList<>();
    results.add(fileSplitResult);
    return ResultVo.ok(results);
  }

  public List<TextSegment> split(String markdown) {
    Document document = new Document(markdown);
    // 使用较大的块大小（2000）和相同的重叠（400）
    DocumentSplitter splitter = DocumentSplitters.recursive(2000, 400, new OpenAiTokenizer());
    List<TextSegment> segments = splitter.split(document);
    return segments;
  }
}
```

`id` 直接取自上传结果，`parse_strategy` 与 `page_count` 用于排查「为什么这篇文档没解析出内容」，`page_count` 对非 PDF 为 0。注意当前前端**尚未展示**这两个字段，接口已返回但 UI 未消费。

## 测试覆盖

解析器的关键分支都有单元测试，且**普通测试不打付费接口**：测试通过覆写 `ocr` / `ocrPdfPage` / `readOcrCache` / `writeOcrCache` / `recognize` 来替换远端调用。

```java
package nexus.io.mosskb.service.kb;

import java.io.ByteArrayOutputStream;

import java.util.zip.ZipEntry;

import org.junit.Test;
import static org.junit.Assert.*;

public class DocumentParsingServiceTest {
  private static class Parser extends DocumentParsingService {
    int ocrCalls;
    @Override
    protected String ocr(byte[] data, String filename) {
      ocrCalls++;
      return "Scanned content " + ocrCalls;
    }
    @Override
    protected String ocrPdfPage(String sourceHash, int page, byte[] data) {
      return ocr(data, "page.pdf");
    }
  }

  @Test
  public void pdfUsesTextAndOcrPerPageInOriginalOrder() throws Exception {
    try (PDDocument pdf = new PDDocument(); ByteArrayOutputStream out = new ByteArrayOutputStream()) {
      PDPage first = new PDPage();
      pdf.addPage(first);
      try (PDPageContentStream canvas = new PDPageContentStream(pdf, first)) {
        canvas.beginText();
        canvas.setFont(PDType1Font.HELVETICA, 12);
        canvas.newLineAtOffset(40, 700);
        canvas.showText("Native administrative review document with sufficient readable text for extraction.");
        canvas.endText();
      }
      pdf.addPage(new PDPage());
      pdf.save(out);
      Parser parser = new Parser();
      DocumentParsingService.Parsed result = parser.parse(out.toByteArray(), "misleading.txt");
      assertEquals("pdf-mixed", result.strategy());
      assertEquals(2, result.pages());
```

这条用例同时锁定了三件事：**内容优先于扩展名**（`.txt` 的扫描混合 PDF 仍解析为 `pdf-mixed`）、**页序不乱**（原生页文本出现在 OCR 文本之前）、**只对需要 OCR 的页发起调用**（`ocrCalls == 1`）。

缓存复用也有独立用例，模拟两次上传同一份 PDF 但文件名不同：

## 结论

多文档解析的核心是**先看内容再选策略**：PDF 与 DOCX 靠魔数判定，PDF 逐页在文本提取与 OCR 之间切换，DOCX 在结构提取与内嵌图片 OCR 之间切换，表格与旧版 Word 各走独立通道，ZIP 只作为受限的文档集合递归解析。所有远程 OCR 结果按「内容 MD5 + 模型」或「原始文件 + 页码」缓存，失败与超时都给出可追踪的错误信息。

落地时按顺序核对：上传阶段前后端各拦一次 100 MB；解析阶段确认 `parse_strategy` 与预期一致；预览阶段确认分段数与页序正常；提交阶段确认 `id` 与 `name` 原样回传。这样从上传到入库的链路就完整了。
