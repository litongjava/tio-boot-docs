# 多文档解析

[[toc]]

将文档转为 pdf,然后在进行解析

## 当前实现与接口说明

Java 后端先检测文件实际内容，再选择解析策略。当前处理 PDF、DOCX、DOC、XLS/XLSX、常用文本和 HTML、可识别图片及受限 ZIP 文档集合。不要仅凭文件扩展名决定解析方式，也不要将尚未实现的格式列为已支持。

文字 PDF 使用文本提取，扫描页使用 Gitee PaddleOCR-VL-1.5，混合 PDF 逐页选择；DOCX 保留正文和表格，正文极少且含图片时对内嵌图片 OCR；表格按工作表提取。完整格式、容量限制和策略标识见[文档检测与解析策略](29.md#文档检测与解析策略)。

解析预览返回文件 `id`、策略与页数。前端提交确认后的分段时必须回传该文件 ID，后端据此建立文档关联。解析结果应由用户检查后再入库。

## 分段确认请求

```http
POST /api/dataset/{datasetId}/document/_bach
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
```

```json
[{"id":"<解析返回的文件ID>","name":"资料.docx","paragraphs":[{"title":"标题","content":"经确认的正文"}]}]
```

文件 ID 用于关联上传文件，知识库 ID 用于授权和选择向量模型。不要在前端确认时丢弃文件 ID。
