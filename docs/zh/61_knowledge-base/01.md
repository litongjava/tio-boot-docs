# 数据库设计与初始化

[[toc]]

当前 Java MaxKB 使用 PostgreSQL、pgvector 和 pg_trgm。文档与查询向量均为 1024 维，不应将历史教程中的其他维度表结构直接用于当前服务。

## Windows 安装扩展

`extension "vector" is not available` 表示正在运行的 PostgreSQL 服务端尚未安装扩展文件。需要匹配数据库安装目录和架构，编译安装 `vector.dll`、`vector.control` 及 SQL 文件，再在实际业务数据库启用扩展。完整 Windows 步骤见[部署文档](29.md)。

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
SELECT extname FROM pg_extension WHERE extname IN ('vector', 'pg_trgm');
```

扩展安装目录属于服务器，不是 JDBC 客户端目录。已有业务数据库不应重复创建或删除；使用 `my.txt` 中的实际数据库名及访问凭据。

## 初始化和迁移

在 Java 项目根目录执行：

```powershell
.\scripts\Initialize-Database.ps1 -PostgresBin '<PostgreSQL安装目录>\bin'
```

脚本顺序执行 `init-db.sql` 和 `002` 至 `009` 的迁移，覆盖默认 Gitee 模型、文件名长度、关键词检索、会话摘要、Python 函数、用户 token_version、数据库模型目录及目录快照。新增结构采用幂等创建；升级前备份已有数据库，检查旧表维度和字段，不把 `IF NOT EXISTS` 理解为自动转换所有旧结构。

## 核心表

| 数据 | 表或字段 |
| --- | --- |
| 账号与认证 | `max_kb_user`，含 `is_active`、`deleted`、`token_version` |
| 平台及候选模型 | `max_kb_model_provider`、`max_kb_model_catalog` |
| 用户配置模型 | `max_kb_model`，含凭据、归属及参数表单 |
| 知识库与文档 | `max_kb_dataset`、`max_kb_document` |
| 分段与向量 | `max_kb_paragraph`，向量维度 1024 |
| 向量缓存 | `max_kb_embedding_cache`，模型空间与内容摘要共同区分缓存 |
| 问题及关联 | `max_kb_problem`、`max_kb_problem_paragraph_mapping` |
| 应用与知识库关联 | `max_kb_application`、`max_kb_application_dataset_mapping` |
| 会话及问答 | 聊天、问答记录和摘要迁移中定义的表 |

可执行表结构以 Java 项目的初始化及迁移脚本为准，不在文章中维护另一份逐渐失配的完整 SQL。模型目录与迁移细节见[35](35.md)，账号和令牌策略见[34](34.md)。
