## 1. 创建用户、授予权限及安装 `pgvector` 插件

以下步骤演示了在 PostgreSQL 中创建新用户和数据库，授予必要权限，并安装及测试 `pgvector` 插件的过程。

#### 1.1 切换到 PostgreSQL 用户

```bash
su - postgres
```

#### 1.2 连接到 PostgreSQL

```bash
psql
```

#### 1.3 创建数据库和用户

在 `psql` 提示符下执行以下命令，以创建名为 `max_kb` 的数据库以及同名用户，并设置密码：

```sql
-- 创建数据库
CREATE DATABASE max_kb;

-- 创建用户并设置密码
CREATE USER max_kb WITH PASSWORD '<替换为自己的数据库密码>';
```

#### 1.4 授予用户权限

```sql
-- 授予用户 max_kb 对数据库 max_kb 的所有权限
GRANT ALL PRIVILEGES ON DATABASE max_kb TO max_kb;

-- 切换到 max_kb 数据库
\c max_kb

-- 授予用户 max_kb 在 public 模式下创建表的权限
GRANT ALL PRIVILEGES ON SCHEMA public TO max_kb;
```

> **提示**：在大多数情况下，无需更改 `public` 模式的所有者，除非有其他特殊需求。

#### 1.5 安装并启用 `pgvector` 插件

1. **安装插件**（以基于 Debian/Ubuntu 的系统为例，需根据自身 PostgreSQL 版本调整命令）：

   ```bash
   sudo apt-get update
   sudo apt-get install postgresql-14-pgvector
   ```

2. **启用插件**：

   ```sql
   -- 再次确保在 max_kb 数据库下
   \c max_kb

   CREATE EXTENSION IF NOT EXISTS vector;
   ```

3. **验证是否成功启用**：

   ```sql
   SELECT * FROM pg_extension WHERE extname = 'vector';
   ```

   如果能查询到返回结果，则表示扩展已启用。

#### 1.6 测试 `pgvector`

在数据库中创建一个测试表，确认 `vector` 类型可用：

```sql
CREATE TABLE vector_test (
    id SERIAL PRIMARY KEY,
    v VECTOR(3)
);
```

如果能成功创建表，说明 `pgvector` 已正常启用。

## 2. 数据库设计

以下是本项目所需的主要数据表结构与示例创建脚本。

### 2.1 设计规范

- **主键**：统一使用 64 位的雪花 ID（Snowflake ID），`BIGINT` 类型。
- **租户 ID**：所有表均增加 `tenant_id`，默认为 0。
- **逻辑删除**：多数表均包含 `deleted` 字段，建议使用 `0` 表示正常，`1` 代表已删除。实际生产环境中也可采用其他标志位或多租户/软删除策略。
- **时间戳**：采用 `TIMESTAMP WITH TIME ZONE` 或 `TIMESTAMP WITHOUT TIME ZONE` 存储创建/更新时间，具体可视业务需求调整。
- **向量列**：`embedding`、`title_embedding` 等使用 `VECTOR` 类型且不写死维度，维度由 Embedding 模型决定（当前部署为 1024 维）。
- **例外**：后期增量表（`max_kb_chat_context`、`max_kb_function_lib`、`max_kb_model_provider`、`max_kb_model_catalog`）是平台/缓存/附属表，不带 `tenant_id`；其中 `max_kb_function_lib` 的 `deleted` 为 `BOOLEAN`，与基础表的 `SMALLINT` 约定不同，各表下已单独标注。

  "email" varchar_pattern_ops
);
CREATE INDEX "user_username_index_like" ON "public"."max_kb_user" USING btree (
  "username" varchar_pattern_ops
);

-- 插入初始记录（管理员账户）

## 当前增量表结构及迁移

保留上文基础表和字段说明。当前程序通过 `scripts/Initialize-Database.ps1` 顺序执行初始化及增量脚本。`IF NOT EXISTS` 不会自动改变旧列类型；旧向量空间与新模型不能混用。表 24–27 就是这些脚本建出的表，本节给出脚本清单与字段级变更。

```powershell
.\scripts\Initialize-Database.ps1 -PostgresBin '<PostgreSQL安装目录>\bin'
```

### 增量脚本清单

| 脚本 | 作用 | 关联对象 |
| --- | --- | --- |
| `init-db.sql` | 建基础表及索引，写入管理员账号 | 表 1–23 |
| `002-gitee-models.sql` | 写入默认 Gitee 平台模型 1001/1002 | `max_kb_model`、`max_kb_dataset.llm_mode_id` |
| `003-filename-capacity.sql` | 放宽文件名长度 | `max_kb_file.filename` |
| `004-keyword-search.sql` | 安装 `pg_trgm`，支撑模糊/关键词检索 | 扩展，非表 |
| `005-agent-context.sql` | 建会话摘要与压缩水位表 | 表 24 |
| `006-python-functions.sql` | 建隔离执行的函数库表 | 表 25 |
| `007-user-sessions.sql` | 令牌版本，用于让旧令牌失效 | `max_kb_user.token_version` |
| `008-model-catalog.sql` | 建平台与模型目录表并初始化表单 | 表 26、表 27、`max_kb_model.model_params_form` |
| `009-model-catalog-snapshot.sql` | 登记模型目录快照数据 | 表 27 的数据 |

### 字段级变更

基础建表脚本不含下列列，历史库需按顺序执行。`ADD COLUMN IF NOT EXISTS` 可重复执行，但不会改变已存在列的类型，`ALTER COLUMN ... TYPE` 必须显式执行：

```sql
ALTER TABLE max_kb_user    ADD COLUMN IF NOT EXISTS token_version BIGINT NOT NULL DEFAULT 0;
ALTER TABLE max_kb_dataset ADD COLUMN IF NOT EXISTS llm_mode_id BIGINT;
ALTER TABLE max_kb_model   ADD COLUMN IF NOT EXISTS model_params_form JSONB NOT NULL DEFAULT '[]';
ALTER TABLE max_kb_file    ALTER COLUMN filename TYPE TEXT;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

### 向量空间一致性

切换 Embedding 模型时，`max_kb_embedding_cache` 与 `max_kb_paragraph`、`max_kb_sentence` 中的旧向量维度与新模型不一致，检索会直接报维度错误。此时不能只改模型 ID，需要先清空缓存并对文档重新向量化。

平台表不保存用户 API Key；凭据由用户模型实例管理。`008-model-catalog.sql` 还初始化平台与表单，`009-model-catalog-snapshot.sql` 登记模型目录快照。目录更新不需要重新编译，完整接口及数据关系见第 35 章。
