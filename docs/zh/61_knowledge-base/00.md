# Java MaxKB 系统设计

Java MaxKB 使用 tio-boot 承载 HTTP API，复用 MaxKB 前端，使用 PostgreSQL 保存用户、知识库、文档、向量及会话记录。远程模型承担推理、向量生成和 OCR，本机无需加载模型权重。

## 数据流

文档上传后先检测实际内容。可提取文字的文档走本地结构提取，扫描页和图片走远程 OCR；用户确认分段后，使用知识库选择的向量模型生成 1024 维向量，再事务保存文档与片段。

一次提问先读取当前会话摘要与未压缩问答，再改写检索问题，执行“检索 → 证据核验 → 缺口检索”的有限循环。资料充分、达到轮次上限或没有新增证据时停止，使用累计资料生成最终回答并保存问答记录。历史只用于理解上下文，不作为知识库事实证据。

## 配置与隔离

平台目录、基础模型目录和用户模型实例分别入库；用户可输入平台提供的模型 ID。账号之间按资源所有者隔离，公有模型及主动分享的聊天按各自访问规则处理。上下文仅在 token 超预算时压缩。隔离 Python 执行器需要容器环境，环境未就绪时拒绝执行。

## 验证方法

功能验证覆盖文档检测、模型请求、检索循环、压缩阈值、账号权限及 UI 追问。检索质量和响应耗时应使用实际业务测试集分别测量；本章不把未留存测试依据的准确率、吞吐量或延迟数字作为实验结论。
