# tio-http-server 与 tio-boot 的使用边界

`tio-http-server` 提供 HTTP 服务与 Handler 等底层能力；`tio-boot` 在其上提供应用启动、配置、Controller、拦截器和扩展集成。两者文档中的启动方式不能直接混合。

## 如何选择

| 需求 | 阅读入口 |
| --- | --- |
| 独立创建基础 HTTP 服务，自己组织生命周期 | [基础 HTTP 服务](<01.md>) |
| 在已有 tio-boot 中增加路由 | [增加 HttpRequestHandler](<02.md>)、[Handler 入门](<../06_web/30.md>) |
| 自行处理参数和返回值 | [Handler 常用操作](<05.md>)、[方法与错误响应](<../06_web/32.md>) |
| 查找 Handler 与 Controller 的优先级 | [分发源码说明](<../71_tio-boot/04.md>) |

已有 tio-boot 服务时，通过其 `TioBootServer` 路由器注册 Handler 即可。不要为了增加一个路径，再在同一端口启动第二个基础 HTTP 服务。

## 不能混用的假设

- 裸 HTTP 服务没有自动执行业务工程的 `BootConfiguration`；需要由其启动代码完成相应配置。
- `TioBootTest` 只帮助初始化环境和 AOP，不会自动监听 HTTP 端口。
- Handler 路由存在不表示数据库、存储或鉴权已配置。
- 在 tio-boot 中返回 null 的后续分发行为应以其分发器为准，不能仅根据基础服务示例推断。

完成接入后至少验证实际外部地址、HTTP 方法、异常响应和关闭资源行为；测试方法见 [真实 HTTP 测试](<../17_tests/02.md>)。
