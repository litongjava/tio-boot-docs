# 操作浏览器指令

> 阅读定位：本章保留与 [Controller 入门示例](./06.md) 配套的接口说明，用于学习参数绑定、响应体、元素索引和批量执行。下文 79 个接口及 `/api/v1/playwright/` 地址属于该教学方案，不能当作当前服务 API；当前 116 个命令见 [13](./13.md)，请求格式见 [08](./08.md)，实现教程从 [17](./17.md) 开始。

浏览器操作全部通过 HTTP 接口暴露，接口前缀为 `http://localhost:10049/api/v1/playwright/`（端口取自 `app.properties` 中的 `server.port`）。本教学示例的 `PlaywrightController` 共提供 79 个接口，按功能分组如下：

* **导航**：`start`、`navigate`、`go_to_url`、`get_dom_text`、`go_forward`、`reload`、`get_url`、`get_title`、`go_back`、`wait`、`close`
* **元素交互**：`click_element_by_index`、`input_text`、`upload_file`、`extract_structured_data`、`scroll`、`send_keys`、`scroll_to_text`、`get_dropdown_options`、`select_dropdown_option`、`execute_js`、`double_click_element_by_index`、`hover_element_by_index`、`focus_element_by_index`、`check_element_by_index`、`uncheck_element_by_index`、`type_text`、`drag_element_by_index`、`key_down`、`key_up`
* **信息读取**：`get_element_text`、`get_element_html`、`get_element_value`、`get_element_attribute`、`get_element_count`、`get_element_box`
* **状态查询**：`is_visible`、`is_enabled`、`is_checked`
* **定位方式**：`click_element_by_selector`、`input_text_by_selector`、`click_element_by_text`、`click_element_by_role`、`input_text_by_label`
* **标签页**：`switch_tab`、`close_tab`、`get_tabs`、`new_tab`
* **等待**：`wait_for_element`、`wait_for_text`、`wait_for_url`、`wait_for_load`、`wait_for_function`
* **鼠标**：`mouse_move`、`mouse_down`、`mouse_up`、`mouse_wheel`
* **截图与 PDF**：`screenshot`、`pdf`
* **Cookie 与存储**：`get_cookies`、`set_cookie`、`clear_cookies`、`get_local_storage`、`set_local_storage`、`clear_local_storage`
* **浏览器设置**：`set_viewport`、`set_geolocation`、`set_offline`、`set_headers`、`set_credentials`、`set_media`
* **弹窗与控制台**：`get_dialog`、`set_dialog_behavior`、`get_console_logs`、`clear_console_logs`
* **网络**：`route`、`unroute`、`get_requests`
* **批量**：`commands`

## 通用约定

### 统一响应体

所有接口返回同一个响应体结构：

```json
{"data":{},"code":1,"ok":true,"error":null,"msg":null}
```

* 成功时 `code` 为 `1`、`ok` 为 `true`，`error` 与 `msg` 为 `null`，业务数据放在 `data` 中，`data` 可以是空对象。
* 失败时 `code` 为 `0`、`ok` 为 `false`，`msg` 是中文失败原因，例如 `没有找到对应的浏览器实例：1234567890123456`、`click_element_by_index 索引越界: 9,当前没有页面快照,请先调用 get_dom_text 获取元素索引`。
* 未捕获异常（例如缺少必需参数触发空指针）不经过响应体包装，直接返回裸 HTTP 500。
* `id` 是 Long 型雪花 ID，序列化成字符串，例如 `"1234567890123456"`。下表“返回示例”一列只列出 `data` 的内容。

### 参数绑定

* 除 `execute_js` 与 `commands` 以外的接口都是老式多参数方法，参数只从 query 或表单（`application/x-www-form-urlencoded`）读取，**JSON 请求体不生效**；缺少必需参数时会触发空指针并返回 HTTP 500。
* `execute_js` 走 `HttpRequest.getRequestMap()`，query、表单、JSON 请求体三种方式都支持，同名字段以 JSON 请求体优先。
* `commands` 更严格：**必须用 POST + JSON 请求体**，命令只能写在请求体里，查询串里只允许出现可选的 `id`（见“批量”一节）。
* 布尔、数字参数同样按字符串传递，例如 `headless=true`、`seconds=3`、`x=100`。

### 元素索引

`get_dom_text` 返回的 `data.text` 每行形如 `[index]<tag attr='value'>文本/>`，其中的 `index` 就是按索引接口要用的元素索引，可用于 `click_element_by_index`、`input_text`、`upload_file`、`get_dropdown_options`、`select_dropdown_option`、`double_click_element_by_index`、`hover_element_by_index`、`focus_element_by_index`、`check_element_by_index`、`uncheck_element_by_index`、`type_text`、`drag_element_by_index`、`get_element_text/html/value/attribute/box`、`is_visible/is_enabled/is_checked`。

* 索引优先取最近一次 `get_dom_text` 生成的 DOM 树快照。
* 没有快照时，`click_element_by_index` 等老接口会回退成 CSS 选择器顺序索引：点击类为 `a, button, input[type=button], input[type=submit]`，输入类为 `input, textarea`，上传为 `input[type=file]`，下拉框为 `select`；而新增的按索引读取类接口在没有快照时直接报错，要求先调用 `get_dom_text`。
* 按索引操作元素的等待上限是 5 秒，超时后报错信息会提示重新调用 `get_dom_text` 获取元素索引。
* 页面发生变化（导航、点击跳转、动态渲染）后必须重新调用 `get_dom_text`，旧索引会失效。

### 快照文本怎么读

`data.text` 是给模型读的页面文本，每行形如 `[index]<tag attr='value'>文本/>`。只看格式容易误判，下面是真实样例（百度首页）与逐条解释：

```text
[Start of page]
		[0]<a >新闻/>
		[8]<a />
			[9]<a name='tj_briicon'>更多/>
		[12]<a name='tj_login'>登录/>
							[14]<input name='wd' placeholder='肖战连续两天请剧组喝冰饮'/>
							[15]<input type='submit' value='百度一下'/>
							[16]<a >AI搜索已支持「DeepSeek-R1」最新版 立即体验/>
								[17]<div > />
						[19]<li />
							[20]<a > 0 以历史的纵深感做好今天的工作/>
						[21]<li >新/>
							[22]<a > 5 亲叔叔炮轰宗馥莉：她从不与宗家往来/>
			[39]<div >辅助模式/>
				[40]<div />
[End of page]
```

上面是节选。其中的 `[Start of page]` 与 `[End of page]` 是测试/demo 代码（`DomServiceTest`、`PlayWrightTaobaoSearch`、`PlayWrightKeheLogin`）用 `System.out.println` 打印的边界标记，**`get_dom_text` 接口本身不产生这两行**：实测 `data.text` 的第一行直接就是 `[0]<a >新闻/>`。

| 现象 | 含义 |
| --- | --- |
| `[Start of page]` / `[End of page]` | 边界标记，只出现在 `src/test` 下测试/demo 代码（`DomServiceTest`、`PlayWrightTaobaoSearch`、`PlayWrightKeheLogin`）的 `System.out.println` 里，`get_dom_text` 接口不返回这两行。**不是页面元素**：没有索引，不能用于任何按索引接口 |
| 行首缩进（制表符） | DOM 嵌套层级，嵌套关系只靠缩进表达：`[20]` 缩进在 `[19]<li />` 之下，说明这条新闻链接属于那个 `li`；`[17]<div > />` 缩进在 `[16]<a>` 之下 |
| `[index]` | 元素索引，所有按索引操作的接口都用它。**编号不连续**（`[12]` 后面直接是 `[14]`），因为只有 buildDomTree 判定为可交互的节点才会分配索引，不要把它当行号或“第 n 个元素” |
| 行尾 `/>` | 只是格式化后缀，**不代表自闭合**：`[0]<a >新闻/>` 里的 `新闻` 就是链接文字 |
| `<a />`、`<span />`、`<div />` 这类没有文字的行 | 没有可见文字的节点：图标、装饰、空容器。它有索引就说明可以点 |
| `[17]<div > />`（尖括号里只有一个空格） | 该节点没有任何被保留的语义属性，文本也只有一个空格 |
| 属性 | 只保留部分语义属性，实测有 `type`、`placeholder`、`aria-label`、`title`、`name`、`value`；**没有 `id`、`class`、`href`、`style`**，所以从快照里看不出链接地址、也认不出 CSS 类名。源码保留的语义属性还包括 `checked`、`role`、`alt`、`aria-expanded`、`aria-checked`、`data-state`、`data-date-format` |
| `value='百度一下'` | 按钮类 input 上的按钮文字；输入框上出现的 `value` 是**当前值**（实测在必应搜索框输入后，快照里出现 `[2]<input type='search' name='q' value='Mac Mini M4' .../>`），但要确定地读值应该用 `get_element_value` |
| 文本顺序 | DOM 顺序。`[21]<li >新/>` 的 `新` 是角标文字，真正的链接文字在它内部的 `[22]` 里 |

几条容易踩的实测结论：

* **不可见的元素不会出现在快照里，选择器类接口也操作不了它**：百度首页真实的搜索框是 `INPUT#kw name=wd type=text`，但它 `offsetParent === null`（已被新的 AI 输入框取代而隐藏），所以快照里根本没有它，快照里只会出现当前真正可见、且被判定为可交互的输入框与按钮。此时用选择器去操作它同样无效：`input_text_by_selector?selector=%23kw` 会等满 5 秒后失败，返回 `input_text_by_selector 失败：没匹配到可操作的元素(不存在或不可见): 选择器 #kw`；`click_element_by_text` 对不存在的文本也一样，返回 `click_element_by_text 失败：没匹配到可操作的元素(不存在或不可见): 文本 不存在的文字xyz`。原因是隐藏元素不满足可操作性检查，**选择器、文本、角色、标签这几类定位接口都要求元素可操作**。
* 这类元素只能用 `execute_js` 兜底：直接设值并派发 `input` 事件（实测有效，返回 `{"data":{"result":"Mac Mini M4"},"ok":true}`）：

  ```shell
  curl -s -G "http://localhost:10049/api/v1/playwright/execute_js" \
    --data-urlencode 'id=1234567890123456' \
    --data-urlencode 'body=(function(){var e=document.querySelector("#kw");e.focus();e.value="Mac Mini M4";e.dispatchEvent(new Event("input",{bubbles:true}));return e.value;})()'
  ```
* **快照会过期**：点击、跳转、异步渲染之后索引会重新计算，必须重新调用 `get_dom_text`，沿用旧索引只会得到索引越界或等待超时。

要按 `id`、`class`、`href` 定位时，用选择器类接口（`click_element_by_selector`、`input_text_by_selector`）或 `execute_js`（例如 `document.querySelectorAll('a')[0].href`）；注意选择器类接口要求元素可操作，隐藏元素只能走 `execute_js`（见上面几条实测结论）。

| `http://localhost:10049/api/v1/playwright/get_title` | `id` (Long) | `{"title":"示例站点"}` |
| `http://localhost:10049/api/v1/playwright/go_back` | `id` (Long) | `{"status":200,"url":"https://example.com/a"}` |

| `http://localhost:10049/api/v1/playwright/close` | `id` (Long) | `{}` |

说明：

* `start` 传已有 `id` 时复用该实例，不传则生成新的雪花 ID；`id` 在响应中是字符串。
* `go_to_url` 与 `navigate` 功能相同，只是单独的接口。
* `get_dom_text` 返回 AI 可读的结构化页面文本与元素索引，是理解页面、拿到元素索引的唯一入口：

  ```json
  {
    "url": "https://example.com/",
    "title": "示例站点",
    "text": "[0]<a >首页/>\n[1]<input name='q' />",
    "tabs": [{ "index": 0, "url": "https://example.com/", "title": "示例站点", "current": true }],
    "pixels_above": 0,
    "pixels_below": 1200,
    "viewport_height": 900,
    "page_height": 2100
  }
  ```

  参数 `highlight` 控制是否在页面上绘制高亮框（默认绘制），`viewportExpansion` 是视口外扩像素（默认 0）。调用后该次快照会被缓存，供按索引接口使用。`data.text` 的逐条读法（含真实样例）见上文“快照文本怎么读”。
* `go_back` 与 `go_forward` 用 URL 是否变化判断是否有历史记录，没有可用历史记录时返回 `code` 为 `0`、`msg` 为 `无法后退：没有可用历史记录`（前进对应 `无法前进：没有可用历史记录`）。对 `about:blank` 这类没有 HTTP 响应的页面，`status` 为 `0`。
* `wait` 等待指定秒数，`seconds` 必须显式传入。

* `drag_element_by_index` 从 `index` 拖到 `targetIndex`，两个索引都来自 `get_dom_text`。
* `upload_file` 的 `path` 是服务器上的文件路径。
* `extract_structured_data` 的 `text` 取 `document.body.innerText`，最多 20000 字符，读取前会临时隐藏高亮层，避免高亮序号混进正文；`extractLinks` 为 `true` 时额外返回 `links`（每项含 `text` 与 `href`）。

* `send_keys` 直接按下组合键（如 `Enter`、`Control+o`），`key_down`/`key_up` 用于单独按下与释放。
* `get_dropdown_options` 与 `select_dropdown_option` 只适用于原生 `select` 元素，后者按选项文本选择。

## 批量

`commands` 把一组命令打包成一次请求执行，是 **PTC（Programmatic Tool Calling）** 的入口：一次请求下发一整个计划，把动作和读取混排（末尾放一个 `get_dom_text`），一次模型推理就能拿到全部观察结果，从而减少推理步数与往返时间。

| 接口 | 参数 | 返回示例（`data` 字段） |
| --- | --- | --- |
| `http://localhost:10049/api/v1/playwright/commands` | `id` (Long，可选：放在请求体里，数组体时放查询串 `?id=`)、命令 JSON 请求体（POST 必需） | 见下方“逐步结果” |

### 请求写法

`commands` **只接受 POST + JSON 请求体**：命令必须放在请求体里，请求体可以是对象载荷、命令数组，也可以只写一条命令。

| 写法 | 请求体 | 说明 |
| --- | --- | --- |
| **POST + 对象载荷**（推荐） | `{"id":...,"stopOnError":...,"commands":[...]}` | `id`、`stopOnError`、`commands` 全在请求体里，查询串不用带参数 |
| **POST + 命令数组** | `[{"命令名":{参数}}, ...]` | 数组体带不了 `id`，所以要在查询串里传 `?id=...`（POST 带查询串是允许的） |
| POST + 单条命令 | `{"id":...,"get_title":{}}` | 不含 `commands` 键、且除 `id`、`stopOnError` 外只剩一个命令键的对象，会被当成单条命令 |

```shell
# 1) POST + 对象载荷（推荐）
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"id":1234567890123456,"stopOnError":false,"commands":[{"get_title":{}},{"get_url":{}}]}' \
  "http://localhost:10049/api/v1/playwright/commands"

# 2) POST + 命令数组（id 必须放查询串）
curl -s -X POST -H 'Content-Type: application/json' \
  -d '[{"get_title":{}}]' \
  "http://localhost:10049/api/v1/playwright/commands?id=1234567890123456"

# 3) POST + 单条命令
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"id":1234567890123456,"get_title":{}}' \
  "http://localhost:10049/api/v1/playwright/commands"
```

**为什么只支持 POST**：

* `/commands` 会改浏览器状态（点击、跳转、输入），不是只读接口，用 GET 语义不对；
* 命令 JSON 塞进 URL 要做百分号编码，还受 URL 长度限制——实测一个 20 条命令的计划编码后已经有 700 多个字符，长计划只能放请求体；
* POST 请求体不受 URL 长度约束，也不必为引号和中文做转义。

因此 GET、表单和 `bodyJson` 字段都不再支持：

| 老写法 | 结果 |
| --- | --- |
| GET（无论带不带查询串） | `批量指令只支持 POST + JSON 请求体,请用 POST 并把命令放在请求体里` |
| POST + 表单（`application/x-www-form-urlencoded`） | 表单体不是 JSON，返回 `请求体解析失败,批量指令需要 JSON：<原因>` |
| POST + `{"id":...,"bodyJson":"[...]"}` | 源码对 `bodyJson` 字段有显式判断，直接返回迁移提示：`不再支持 bodyJson 字段,请把命令直接放在请求体里,例如 {"id":1,"commands":[{"get_title":{}}]}` |

请求体出错时的提示（都是 `code` 为 `0` 的中文 `msg`）：

| 情况 | `msg` |
| --- | --- |
| 请求体为空 | `请求体不能为空,需要命令数组或含 commands 的对象` |
| 请求体不是合法 JSON | `请求体解析失败,批量指令需要 JSON：<原因>` |
| 数组体但没传 `id` | `缺少参数 id,可以放在查询串里,也可以放在对象载荷里` |
| 对象里既没有 `commands`，也不止一个命令键 | `对象载荷必须包含 commands 数组,或者只写一条命令` |
| `commands` 是空数组 | `命令数组为空` |
| 查询串里的 `id` 不是合法数字 | 框架的校验原因，例如 `id must be an integer` |

每项命令对象**只能有一个键**，多于一个键时该步失败并给出 `每条命令对象只能包含一个键`。

### 覆盖范围

* 控制器共 79 个接口，除 `commands` 自身之外的 **78 个接口全部可以作为批量命令调用**；`commands` 不允许嵌套，嵌套时该步返回 `批量接口不支持嵌套调用 commands`。
* 命令名就是接口路径去掉斜杠（例如 `get_dom_text`、`click_element_by_index`），参数名与单独调用时完全一致。
* 其中老 17 个命令（`navigate`、`go_to_url`、`go_back`、`wait`、`click_element_by_index`、`input_text`、`upload_file`、`switch_tab`、`close_tab`、`extract_structured_data`、`scroll`、`send_keys`、`scroll_to_text`、`get_dropdown_options`、`select_dropdown_option`、`execute_js`、`close`）走老的处理器注册表，其余 61 个走新命令表，两者对外表现一致。

### 逐步结果

响应 `data` 里有 `count`、`succeeded`、`failed`、`stopped`、`results`，**每一步的结果都会返回**（这是与老版本最大的区别）：

```json
{
  "data": {
    "count": 3,
    "succeeded": 2,
    "failed": 1,
    "stopped": true,
    "results": [
      { "index": 0, "command": "go_to_url", "ok": true, "data": { "status": 200 }, "msg": null },
      { "index": 1, "command": "get_dom_text", "ok": true, "data": { "text": "[0]<a >新闻/>...", "title": "示例站点" }, "msg": null },
      { "index": 2, "command": "click_element_by_index", "ok": false, "data": null, "msg": "click_element_by_index 索引越界: 999" }
    ]
  },
  "code": 0,
  "ok": false,
  "msg": "第 2 条命令 click_element_by_index 失败：click_element_by_index 索引越界: 999"
}
```

* `results` 每项形如 `{"index":0,"command":"go_to_url","ok":true,"data":{...},"msg":null}`；`index` 从 `0` 开始，与 `msg` 里“第 N 条命令”的 N 是同一个值。
* 每一步的 `data` 原样返回，所以批量里的 `get_dom_text` 能读到 `data.text`、`execute_js` 能读到 `data.result`、`is_checked` 能读到 `data.checked`。
* `count` 是**实际执行**的命令条数：`stopOnError` 生效提前停止时会小于请求里的条数。

### stopOnError

| 取值 | 行为 |
| --- | --- |
| `true`（默认） | 遇到第一个失败就停止，后续命令不再执行，`stopped` 为 `true` |
| `false` | 继续跑完，每一步结果都在 `results` 里，`stopped` 为 `false` |

* 有失败时整体响应仍是 `code` 为 `0`、`ok` 为 `false`，`msg` 形如 `第 2 条命令 click_element_by_index 失败：click_element_by_index 索引越界: 999`（只指出第一条失败），但 `data.results` 完整返回，`succeeded`、`failed` 也照实统计。
* 参数缺失不会返回 HTTP 500，而是该步失败：`第 N 条命令 xxx 失败：缺少参数 index`。
* 布尔参数缺失按 `false` 处理（与单独调用一致），所以批量里 `scroll` 要写 `"down":true` 才向下；`start` 例外，不传 `headless` 按无头处理，避免误弹窗口。
* 未知命令返回 `不支持的命令：xxx(批量接口支持除 commands 之外的全部接口,命令名就是接口路径去掉斜杠)`。

### PTC：一次请求跑完一个计划

一个批次 = 一个计划段：批次里先做动作，末尾放一个 `get_dom_text`，这样下一次推理直接基于最新快照决策，省掉“每个动作一次推理 + 一次单独取快照”。

输入 → 回车 → 等待 → 取快照，一次请求完成：

```shell
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"id":1234567890123456,"stopOnError":false,"commands":[{"input_text":{"index":14,"text":"Mac Mini M4"}},{"send_keys":{"keys":"Enter"}},{"wait_for_text":{"text":"Mac Mini","timeoutSeconds":10}},{"get_dom_text":{}}]}' \
  "http://localhost:10049/api/v1/playwright/commands"
```

一批独立读取用 `"stopOnError":false`，一条失败不影响其它条：

```shell
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"id":1234567890123456,"stopOnError":false,"commands":[{"get_title":{}},{"get_url":{}},{"get_element_text":{"index":0}},{"get_console_logs":{}}]}' \
  "http://localhost:10049/api/v1/playwright/commands"
```

需要循环、条件判断这类逻辑时，在批次里用 `execute_js` 一步做完，不要拆成几十条命令。

## execute_js

`execute_js` 用于执行不在固定指令范围内的页面操作，参数是 `body`，即需要执行的 JavaScript。单独调用时 `body` 直接作为接口参数传入（`execute_js` 支持 JSON 请求体）：

```json
{ "id": 1234567890123456, "body": "document.title" }
```

放进批量批次时，写成命令数组里的一项（POST 对象载荷时 `id` 也放在请求体里）：

```json
[{ "execute_js": { "body": "document.title" } }]
```

`body` 可以是表达式、函数或包含 `return` 的语句片段，执行结果通过 HTTP 接口 `/api/v1/playwright/execute_js` 返回。`execute_js` 可以用 JSON 请求体，也可以走查询串或表单（`id` 与 `body` 放在哪都行，同名字段以 JSON 请求体优先）；`commands` 则必须用 POST + JSON 请求体，其余接口的参数只能放查询串或表单。写法、返回值限制和错误信息见 [启动浏览器](<./06.md>) 的“在页面中执行 JavaScript”一节。
